nelson-lint
Analyseur de code Nelson en ligne de commande.
📝Syntaxe
nelson-lint [--format text|json|sarif] [--config file] path ...
nelson-lint [--include-subfolders true|false] [--fail-on error|warning|info|none] path ...
nelson-lint [--stdin] [--stdin-filename name] [--fix|--fix-dry-run|--diff] path ...
📄Description

nelson-lint analyse les fichiers et dossiers source Nelson depuis la ligne de commande.

--format selectionne une sortie texte, JSON ou SARIF.

--config charge un fichier de configuration JSON version 2.

--include-subfolders active l'analyse recursive des dossiers.

--fail-on selectionne la severite minimale qui produit le code retour 1. --deny warnings reste un alias de --fail-on warning.

--stdin analyse le texte source depuis l'entree standard. Utiliser --stdin-filename pour choisir le nom de fichier des diagnostics.

--quiet supprime la sortie standard, et --output ecrit les diagnostics dans un fichier.

--fix applique les edits de texte surs et non superposes portes par les diagnostics, puis analyse de nouveau les fichiers avant de signaler les diagnostics restants. Les corrections sures incluent le nettoyage des espaces et les autres corrections de l'analyseur dont les plages sont exactes.

--fix-dry-run et --diff affichent les edits surs sans modifier les fichiers.

Le code retour 0 signifie qu'aucun diagnostic ne reste, 1 signifie que des diagnostics restent, et 2 signifie une erreur d'usage, d'entree ou interne.

💡Exemples
Lancer l'analyse recursive avec correction activee.
nelson-lint --include-subfolders true --fix --config nelson-lint.json modules/interpreter/functions
