nelson.compiler.analyze, nelson.compiler.analyze
Examiner les dependances sans produire d'executable.
📝Syntaxe
plan = nelson.compiler.analyze(options)
nelson.compiler.analyze(options)
📥Arguments d'entrée
Paramètre Description
options Un objet scalaire nelson.compiler.BuildOptions.
📤Arguments de sortie
Paramètre Description
plan Structure scalaire decrivant dependances resolues, diagnostics et besoins du runtime.
📄Description

Cette fonction est equivalente a ncc(options, '--explain-link'). Elle lit les sources, les ressources incluses et le catalogue des fonctions chargees. Elle n'execute pas le point d'entree, ne cree pas le dossier de sortie, ne construit pas d'executable et ne copie pas de runtime.

plan.complete indique si l'analyse s'est terminee sans dependance non resolue. Examiner les diagnostics lorsque cette valeur est false. Un plan statique complet ne prouve pas que tous les appels dynamiques et chemins de ressources possibles sont couverts.

plan.runtime decrit les besoins du runtime ; plan.runtime.modules liste les modules selectionnes. plan.noConsole et plan.executableVersion refletent la configuration du lanceur. Les autres champs decrivent les fonctions et ressources resolues, les exclusions et les raisons d'inclusion.

Utiliser AdditionalFiles pour les chemins calcules dynamiquement et examiner les diagnostics avant construction. L'analyse reflete les fichiers et l'environnement courants. Elle ne fige pas les entrees : build effectue une nouvelle analyse.

Sans sortie, le plan est affiche. Avec une sortie, la structure peut etre examinee ou convertie avec jsonencode. Le rapport peut contenir des chemins absolus de la machine de construction.

💡Exemples
Examiner une configuration
options = ncc('options', 'app_entry.m', 'RuntimeMode', 'installed');
plan = nelson.compiler.analyze(options);
disp(plan.complete);
disp(plan.runtime.modules);
