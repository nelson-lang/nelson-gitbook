nelson-lint
Command-line Nelson code analyzer.
📝Syntax
nelson-lint [--format text|json|sarif] [--config file] path ...
nelson-lint [--include-subfolders true|false] [--fail-on error|warning|info|none] path ...
nelson-lint [--stdin] [--stdin-filename name] [--fix|--fix-dry-run|--diff] path ...
📄Description

nelson-lint analyzes Nelson source files and folders from the command line.

--format selects text, JSON, or SARIF output.

--config loads a version 2 JSON configuration file.

--include-subfolders enables recursive folder analysis.

--fail-on selects the minimum severity that produces exit code 1. --deny warnings is kept as an alias for --fail-on warning.

--stdin analyzes source text from standard input. Use --stdin-filename to choose the diagnostic filename.

--quiet suppresses standard output, and --output writes diagnostics to a file.

--fix applies non-overlapping safe text edits carried by diagnostics, then analyzes the files again before reporting the final diagnostics. Safe fixes include whitespace cleanup and other analyzer fixes whose ranges are exact.

--fix-dry-run and --diff show the safe edits without changing files.

Exit code 0 means no remaining diagnostics, 1 means diagnostics remain, and 2 means usage, input, or internal error.

💡Examples
Run the analyzer recursively with fixes enabled.
nelson-lint --include-subfolders true --fix --config nelson-lint.json modules/interpreter/functions
