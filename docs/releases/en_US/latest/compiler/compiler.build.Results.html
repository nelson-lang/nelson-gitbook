compiler.build.Results, compiler.build.Results
Inspect a completed standalone build.
📝Syntax
result = compiler.build.standaloneApplication(options)
result = compiler.build.standaloneWindowsApplication(options)
📄Description

Build functions return this object after successfully publishing their output files. Obtain it from a build function rather than constructing it directly. Its public properties are read-only.

BuildType is standaloneApplication or standaloneWindowsApplication. Files is a column cell array containing the executable, then the .nca file when EmbedArchive is false, then readme.txt for end-user distribution, not a recursive runtime inventory or a list of build-time metadata.

IncludedSupportPackages lists registered nmm packages whose files were actually selected for the application. Unused packages are not reported. Files from an explicitly active older registered version are recognized. This is an inventory of retained files' package origins, not a promise to copy each entire package or to run its loader.

Options is a value copy of compiler.build.StandaloneApplicationOptions. RuntimeDependencies is a compiler.runtime.Dependencies object containing the selected runtime file requirements.

The build does not distribute a runtime or create an installer. The executable needs a compatible installed runtime. The result records the build-time file state; changing or deleting files afterward does not update it.

Dependency tables contain absolute build-machine source paths. Review reports before sharing them. File hashes are integrity checks, not publisher signatures.

buildresult.json is also written in OutputDir. Its versioned Nelson schema records artifact names relative to that directory, their SHA256 digests, runtime identity and the complete runtime snapshot. It does not serialize the AppFile and OutputDir settings, but retains absolute runtime source paths for later file verification. It is not a portable runtime, not a signature, and not an external report format. Do not edit its contents. compiler.package.installer consumes results or reports for Windows or Linux application installation. compiler.runtime.customInstaller packages the shared minimal runtime for one or more applications.

Report format 2 records the contract read from the native launcher: startup interface, supported archive versions, runtime discovery version and console or windowed kind. It does not infer capabilities from the installed compiler version. Legacy reports without this contract must be regenerated by rebuilding the application with current native launchers.
